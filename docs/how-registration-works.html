ArtistLedger — How Registration Works

One transaction, end to end · and where the "database" actually lives

What the app is

  • • An onchain registry proving a wallet belongs to a real human artist
  • • Stores verified artists + anchored releases (audio hash, title, contributors)
  • • Anyone can call is_verified_human(audio_hash) — for playlists, sync licensing, x402 payment gating
  • • Disputes can contest a release; upheld disputes penalize reputation

What registering does

  • • One signed tx, four phases: dedup check → leader evidence → validator check → write
  • • Leader re-fetches ~10 public APIs and greps your live bios for the exact ALVERIFY token
  • • Validators verify the leader's evidence is plausible and recompute the score
  • • Score ≥ 70 → artist record + identity indexes written onchain

Where the "database" is

  • • Inside the smart contract itself — GenLayer studionet (chainId 61999), 0x5386…1bE8
  • • TreeMaps are the tables; your wallet address is the primary key
  • • Every validator node keeps a replica; only consensus txs can change it
  • • Registration references it twice: dedup reads the indexes first, the pass writes them
